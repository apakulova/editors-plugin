# Чистовик

[![Автоматические тесты](https://github.com/apakulova/editors-plugin/actions/workflows/tests.yml/badge.svg)](https://github.com/apakulova/editors-plugin/actions/workflows/tests.yml)

«Чистовик» — Figma-плагин для быстрой чистки русской типографики в текстовых слоях. Он приводит кавычки, тире, пробелы, числа, телефоны, сокращения и базовые символы к единым правилам, не создавая новые текстовые слои и не удаляя старые.

Плагин рассчитан на редакторскую проверку макетов: можно запустить его на одном текстовом слое, на группе/фрейме/компоненте или сразу на всей текущей странице.

## Команды

- `Запустить типограф` — сразу запускает обработку в основном режиме без интерфейса.
- `⭐ Продвинутые фичи` — открывает окно настроек. В интерфейсе есть вкладки `Типограф`, `Правила` и `О плагине`. Рабочий запуск типографа находится на вкладке `Типограф`.
- `⚠️ Не все числа делятся на разряды →` — временный пункт текущего выпуска. Открывает сообщение об изменившейся обработке чисел. В выпусках без активного сообщения этот пункт и разделитель перед ним отсутствуют.

## Что важно

- Плагин изменяет существующие текстовые ноды, а не пересоздает их.
- Текст меняется точечно: плагин использует операции вставки и удаления и не присваивает всему слою новую строку через `textNode.characters`. Если в одном слое больше 256 исправлений, близкие изменения объединяются внутри участка с одинаковым оформлением, чтобы не отправлять Figma тысячи отдельных команд. В однородном длинном слое такой участок может быть большим, но сам текстовый слой не пересоздаётся и его связь с компонентом не меняется.
- Перед точечной записью плагин загружает используемые шрифты и запоминает фактическое оформление. Связанные стили и переменные не переподключаются: точечная запись оставляет существующие связи на месте, а после изменения проверяет их сохранность. Отдельная проверка доступности через Figma API нужна только сохранённому в коде старому режиму полной записи.
- Если во время ожидания изменился сам текст, плагин ничего в этот слой не записывает и просит запустить типограф заново.
- Если во время ожидания изменилось только оформление, плагин перечитывает его, при необходимости загружает новый шрифт и продолжает работу уже с новым оформлением. Перед записью он повторно проверяет, что состояние перестало меняться.
- Если слой удалили до начала записи или во время ожидания, плагин пропускает его и продолжает работу с остальными слоями.
- Смешанное оформление наследуется при каждой точечной вставке и затем проверяется посимвольно: шрифт, размер, заливки, регистр, подчеркивание/зачеркивание, трекинг, высота строки, списки, отступы и абзацные интервалы.
- После успешной записи плагин дополнительно проверяет, что текст остался внутри той же цепочки компонентов и сохранил привязку к текстовому свойству. Главные библиотечные компоненты для этой проверки не загружаются: точечное изменение текста не отсоединяет экземпляр, а ожидание библиотечного оригинала само могло задержать обычный продуктовый экран.
- Непосредственно перед первым изменением создаётся контрольная точка Figma, которая отделяет изменения плагина от предыдущих действий пользователя. Если после записи не удаётся подтвердить оформление или компонентные связи, плагин отменяет в обратном порядке только те точечные вставки и удаления, которые успел выполнить в проблемном слое. Полная запись исходной строки через `characters` при таком возврате запрещена: она сама могла бы сбросить оформление отдельных фрагментов. После подтверждённого восстановления обработка остальных слоёв продолжается; она останавливается только тогда, когда восстановление проблемного слоя подтвердить не удалось.
- На фактическое ожидание всех шрифтов одного запуска даётся общий запас 15 секунд. Применение правил, расчёты, поиск телефонов и запись предыдущих слоёв этот запас не расходуют. Неудачный ответ для одного шрифта запоминается до конца запуска, поэтому следующий слой с тем же шрифтом не ждёт ещё 15 секунд. При следующем отдельном запуске загрузка пробуется заново. Ожидание страницы, а в старом режиме полной записи также библиотечного стиля или переменной, тоже ограничено по времени.
- Переносы строк сохраняются: абзацы не склеиваются.
- Заблокированные слои не обрабатываются по умолчанию. Если замок стоит на текстовом слое, фрейме, группе, секции или другом родителе, текст внутри пропускается. В UI есть чекбокс `Обработать даже слои с замочком`.
- Скрытые слои не обрабатываются по умолчанию. Если скрыт текстовый слой или его родитель, текст внутри пропускается. В UI есть чекбокс `Обработать даже скрытые слои`.
- В `manifest.json` включен `documentAccess: "dynamic-page"`, чтобы Figma не загружала все страницы файла при открытии настроек или быстром запуске.
- В `manifest.json` разрешен сетевой доступ только к `https://chistovik-plugin.vercel.app`: этот адрес принимает техническую аналитику, доставляет её в PostHog и до 18 сентября 2026 года принимает временную диагностику чисел для внутреннего бета-теста.
- Библиотека `typograf` не используется, чтобы встроенные правила не конфликтовали с кастомной логикой.

Если в тексте много ручного форматирования внутри одного слоя, лучше сначала проверить плагин на копии фрейма. В Figma также всегда можно откатить результат через Undo.

## Аналитика плагина

Плагин отправляет анонимные технические события через служебный адрес «Чистовика» на Vercel. Vercel надёжно сохраняет их во временной очереди и доставляет в PostHog Cloud EU с автоматическими повторными попытками. Постоянно данные хранятся в PostHog: начало и результат обработки, режим, область запуска, общие счётчики, время работы, постоянные коды сработавших правил и безопасная категория ошибки. Эти данные нужны для дашбордов и Telegram-отчётов о состоянии плагина.

В постоянную аналитику не отправляются текст макета, названия файлов, страниц и слоёв, email, имя пользователя и Figma user id. Для событий отключено определение местоположения по IP.

До 18 сентября 2026 года включительно внутренняя бета-версия дополнительно отправляет в отдельное временное хранилище диагностические случаи с числами: точный текст до и после обработки, контекстные слова, соседний текстовый слой для проверки, отметку о его влиянии на решение, конкретный признак решения, версию числовых правил и коды сработавших правил. Числа передаются целиком без обезличивания.

Не отправляются имена пользователей, названия и ссылки на файлы, страницы и слои. Диагностические тексты не попадают в PostHog или Telegram. Они доступны только на закрытой странице отчёта и будут удалены после формирования итогового отчёта за 18 сентября.

Аналитика встроена по умолчанию и не отключается в интерфейсе. Она не должна влиять на скорость, уведомления или результат типографики. Если PostHog недоступен, плагин продолжает работать.

Ежедневно Telegram-бот присылает сводку за предыдущий день. Действующие команды:

- `/today` — отчёт за сегодня;
- `/speed` — отчёт по скорости за семь завершённых дней;
- `/errors` — отчёт по ошибкам за семь завершённых дней.

Весь путь данных из Figma через PostHog в Telegram, значения показателей, дашборды, отчёты, команды, приватность и рабочие инструкции описаны в `docs/plugin-analytics.md`.

## Beta-публикация и будущее

Текущая версия опубликована как private organization beta для внутреннего тестирования. В `manifest.json` название временно указано как `Чистовик — Internal Beta`, чтобы beta-версия не смешивалась с будущей публичной версией.

Перед публичной публикацией в Figma Community нужно будет отдельно подготовить production-метаданные: заменить название, `id`, иконку, обложку и описание. Beta-название и beta-идентификаторы не должны переехать в публичный Community-релиз.

## Как обрабатывается выделение

1. Если выбран текстовый слой, обрабатывается только он.
2. Если выбран фрейм, группа, компонент или другой контейнер, обрабатываются все текстовые слои внутри него рекурсивно.
3. Если ничего не выбрано, обрабатываются все текстовые слои на текущей странице.
4. Заблокированные тексты и тексты внутри заблокированных родителей пропускаются, если в UI не включен чекбокс `Обработать даже слои с замочком`.
5. Скрытые тексты и тексты внутри скрытых родителей пропускаются, если в UI не включен чекбокс `Обработать даже скрытые слои`.
6. Технические текстовые слои без содержательных символов, состоящие только из пробелов, табов, переносов строк или неразрывных пробелов, пропускаются всегда.

## Уведомления

Во всех режимах плагин сначала показывает одинаковое небольшое уведомление Figma `Чистовик работает...`. Полностью успешный запуск заканчивается одним из уведомлений ниже. При быстром запуске плагин закрывается только после того, как финальное уведомление исчезло по таймеру или было закрыто пользователем. В окне настроек индикатор работы дополнительно показывается внутри кнопки; после завершения он останавливается, а окно остаётся открытым. Повторный сигнал запуска во время текущей обработки присоединяется к уже идущей работе и не создаёт второй запуск.

- Если были изменения и ничего не было пропущено: `Теперь всё чисто 🔥🔥🔥`
- Если менять было нечего и ничего не было пропущено: `Всё уже было чисто 👌`
- Если были изменения, но часть текстов пропущена из-за замков: `Замочки не тронуты, в остальном — теперь всё чисто 🔥🔥🔥`
- Если изменений не было, но часть текстов пропущена из-за замков: `Замочки не тронуты, а остальное уже было чисто 👌`
- Если были изменения, но часть текстов пропущена из-за скрытия: `Скрытые слои не тронуты, в остальном — теперь всё чисто 🔥🔥🔥`
- Если изменений не было, но часть текстов пропущена из-за скрытия: `Скрытые слои не тронуты, а остальное уже было чисто 👌`
- Если были изменения, но часть текстов пропущена из-за замков и скрытия: `Замочки и скрытые слои не тронуты, в остальном — теперь всё чисто 🔥🔥🔥`
- Если изменений не было, но часть текстов пропущена из-за замков и скрытия: `Замочки и скрытые слои не тронуты, а остальное уже было чисто 👌`

Если обработка завершилась не полностью, красное финальное уведомление заменяется окном того же размера, что настройки:

- `Не всё удалось обработать` — отдельные слои не удалось безопасно изменить, но их исходное состояние подтверждено; плагин продолжил обрабатывать остальные и показывает пропущенные слои;
- `Типограф остановил работу` — исходное состояние одного слоя подтвердить не удалось; окно отдельно показывает этот слой и все слои, до которых обработка не дошла;
- `Не удалось запустить типограф` — ошибка произошла до начала обработки, поэтому список слоёв не показывается.

В окне можно нажать на строку или стрелки, чтобы выделить слой и прокрутить к нему макет. Первый проблемный слой выбирается автоматически. После запуска из настроек есть кнопка `Вернуться к типографу`; после быстрого запуска кнопки нет.

## Правила типографики

Правила применяются в строгом порядке: сначала чистятся пробелы, затем кавычки и пунктуация, математические примеры, тире и дефисы, предварительный разбор чисел и денег, телефоны, сокращения, неразрывные пробелы, математические знаки и символы. В конце дополнительно собираются обратно годы, если рядом с `©` или `г.` они были ошибочно разбиты пробелом.

### 1. Пробелы

- Двойные пробелы заменяются одним.
- Пробелы в начале и конце каждой строки удаляются.
- Пробелы перед `.`, `…`, `:`, `,`, `;`, `?`, `!`, `»`, `)`, `]` удаляются.
- Пробел перед смайликами `:)`, `;)`, `:-)` и `;-)` сохраняется таким, как его поставил автор: `посмеялся:)` или `посмеялся :-)`.
- Пробелы после `«`, `(`, `[` удаляются.
- Пробел между числом и процентом удаляется: `50 %` -> `50%`.
- Пробел между `~` и числом или словом удаляется: `~ 100` -> `~100`.

### 2. Кавычки и пунктуация

- Для кириллицы используются елочки первого уровня: `«...»`.
- Для кириллицы внутри елочек используются лапки второго уровня: `„...“`.
- Если вне кавычек есть кириллица, кавычки оформляются по русским правилам даже вокруг латинских слов: `В тексте есть «Design System»`.
- Если вне кавычек латиница, используются прямые двойные кавычки первого уровня и одинарные кавычки второго уровня, даже вокруг русского слова: `The word "привет"`.
- Кавычка сначала определяется по роли в позиции: открывающая или закрывающая. Только после этого выбирается символ по языку локального контекста и уровню вложенности.
- Для кавычек верхнего уровня язык определяется по строке и по тексту вне всей цитаты верхнего уровня. Текст внутри цитаты и внутри вложенных кавычек не должен перевешивать внешний контекст: `Он сказал "Use 'clean typography' mode"` -> `Он сказал «Use „clean typography“ mode»`, но `He said "Use 'clean typography' mode"` остается английской моделью.
- Вложенные кавычки наследуют язык внешних кавычек. Неправильное направление типографских кавычек исправляется по позиции: `»текст»` -> `«текст»`, `«текст„` -> `«текст“`.
- В режиме `Для разработки` звездочки на местах неразрывных пробелов учитываются как пробельный контекст для кавычек, чтобы повторный запуск не менял уже правильно оформленные кавычки.
- Вложенная русская прямая речь приводится к виду: `«„Как это скучно!“ — воскликнул я невольно».`
- Точка, запятая, точка с запятой и двоеточие выносятся за закрывающую кавычку: `Он сказал «привет».`
- Многоточие не переносится через закрывающую кавычку и остается там, где стояло до обработки: `«привет…»` или `«привет»…`.
- Вопросительный и восклицательный знаки переносятся внутрь закрывающей кавычки: `Он спросил «как дела?»`
- Если внутри закрывающей кавычки уже стоит `?` или `!`, точка сразу после кавычек удаляется: `«как дела?».` -> `«как дела?»`.
- Три точки заменяются многоточием: `...` -> `…`.
- Повторные восклицательные знаки схлопываются: `!!` -> `!`.
- Повторные вопросительные знаки схлопываются: `??` -> `?`.
- Сочетание `!?` нормализуется в `?!`.

### 3. Тире и дефисы

- Дефис или среднее тире между словами с пробелами заменяется длинным тире с пробелами: `слово - слово` -> `слово — слово`.
- Перед длинным тире ставится неразрывный пробел на этапе обработки неразрывных пробелов.
- Дефис между буквами заменяется неразрывным дефисом: `кто-то` -> `кто‑то`.
- Некоторые устойчивые сочетания с ошибочным пробелом собираются с неразрывным дефисом: `из за` -> `из‑за`, `из под` -> `из‑под`, `кто то` -> `кто‑то`, `что либо` -> `что‑либо`, `где нибудь` -> `где‑нибудь`, `кое как` -> `кое‑как`, `все таки` -> `все‑таки`, `всё таки` -> `всё‑таки`.
- Простые компактные диапазоны оформляются длинным тире без пробелов: `5-10 кг`, `5 – 10 кг`, `5 — 10 кг` -> `5—10 кг`; `12:25-13:35` -> `12:25—13:35`; `30.04-12.05` -> `30.04—12.05`; `2001-2019` -> `2001—2019`.
- Составные диапазоны оформляются длинным тире с пробелами вокруг; перед тире затем применяется общее правило неразрывного пробела: `2 000-4 000` -> `2 000 — 4 000`; `1 января-15 августа 2018 года` -> `1 января — 15 августа 2018 года`; `2016-н. в.` -> `2016 — н. в.`.
- Диапазоны с римскими цифрами в ожидаемом контексте оформляются длинным тире без пробелов: `X-XI век`, `I - III главы`, `разделы IV-VI` -> `X—XI век`, `I—III главы`, `разделы IV—VI`.
- Римскими цифрами считаются только последовательности в верхнем регистре из `I`, `V`, `X`, `L`, `C`, `D`, `M`; нижний регистр не меняется: `x-xi`.
- Римские диапазоны обрабатываются только рядом со словами `век`, `глава`, `часть`, `раздел`, `пункт`, `квартал`, `кв.`, `том`, `параграф` и их поддержанными формами. Без такого контекста новое правило римских диапазонов не ставит длинное тире: `X-X` не становится `X—X`. При этом общее правило неразрывного дефиса внутри слов продолжает работать для кириллицы и латиницы: `USB-C` -> `USB‑C`, `X-ray` -> `X‑ray`.
- В начале строки маркер `-` или `–` перед пробелом заменяется на длинное тире.

### 4. Телефоны

Телефоном считается последовательность, если она:

- начинается с `+7`, `7` или `8`;
- содержит ровно 11 цифр после удаления пробелов, скобок и дефисов;
- не стоит после знака `№`;
- не является компактной последовательностью, которую непосредственная валюта доказывает как сумму. Явно оформленный телефон со скобками или телефонными дефисами сохраняет телефонный смысл и рядом с валютой.

Форматирование:

- все разделители внутри номера удаляются;
- код оператора отделяется неразрывными пробелами;
- группы основного номера отделяются неразрывными дефисами;
- номер с `7` получает плюс, номер с `8` остается с восьмеркой.

Примеры:

- `79001234567` -> `+7 900 123‑45‑67`
- `+7 (900) 123-45-67` -> `+7 900 123‑45‑67`
- `+ 7 900 123-45-67` -> `+7 900 123‑45‑67`
- `8 900 123 45 67` -> `8 900 123‑45‑67`
- `9001234567` -> `900 123‑45‑67`
- `900 123-45-67` -> `900 123‑45‑67`

Если код страны и хвост телефона разнесены по разным текстовым слоям, плагин не склеивает слои и не меняет макет. Отдельный слой `+ 7` становится `+7` только рядом с телефонным хвостом из 10 цифр, когда оба слоя являются непосредственными соседями одного горизонтального блока автоматической раскладки без переноса. Поиск по координатам и визуальному расстоянию не используется.

Компактное число рядом с валютой считается суммой, если оно не оформлено как телефон явно: `+79001234567 ₽` -> `+79 001 234 567 ₽`. Запись со скобками или телефонными дефисами сохраняет телефонный смысл: `+7 (900) 123-45-67 ₽` -> `+7 900 123‑45‑67 ₽`.

### 5. Числа, годы и деньги

- Длинное число разбивается на разряды только при достоверном признаке количества: валюте, проценте, единице измерения, масштабе или утверждённом сокращении. `10000 ₽` -> `10 000 ₽`, `10000 кг` -> `10 000 кг`, но `10000` и `10000 клиентов` не получают внутренних разрядных пробелов.
- Знак валюты внутри одного текстового слоя ставится после числа: `$123` -> `123 $`, `₽ 50 тыс.` -> `50 тыс. ₽`. Валютные коды и слова не переставляются. Если знак и число находятся в разных слоях, знак остаётся в своём слое и используется только как признак суммы. Остальные обозначения работают только в точных формах, перечисленных в `docs/typography-rules.md`.
- Одиночная десятичная точка заменяется запятой только рядом с валютой, процентом, единицей измерения или утверждённым сокращением: `10.5 кг` -> `10,5 кг`, а голое `10.5` остаётся без изменений.
- В диапазоне или списке с одним общим обозначением числа меняются целиком либо не меняются: `10000—20000 кг` -> `10 000 — 20 000 кг`, `10000, 20000 и 30000 ₽` -> `10 000, 20 000 и 30 000 ₽`.
- В математическом выражении длинные числа группируются только при наличии `=`: `10000 + 20000 = 30000` -> `10 000 + 20 000 = 30 000`.
- Признак количества может находиться в соседнем текстовом слое только для непосредственных однозначных соседей одного горизонтального блока автоматической раскладки. Скрытые слои, ручное расположение, разные родители и вложенные контейнеры не связываются.
- Точка в нумерации заголовков и документов сохраняется и восстанавливается, если раньше там появилась запятая: `Раздел 1.1`, `§ 2.2`, `ст. 35.1`, `п. 2.1`; `пункт 5,5` -> `пункт 5.5`.
- В начале текстового слоя или новой строки короткая нумерация перед заголовком с большой буквы также сохраняется: `1.1 Как использовать`.
- Нумерация распознаётся после слов `раздел`, `подраздел`, `глава`, `пункт`, `подпункт`, `статья`, `часть`, сокращений `гл.`, `п.`, `ст.`, `ч.` и знаков `§`, `№`.
- Английская запись разрядов и дробной части приводится к русской только рядом с валютой и только целиком: `62,226,338.00 ₽` -> `62 226 338,00 ₽`; та же запись без валюты сохраняется.
- Между числом и валютой, месяцем, единицей измерения или денежно-числовым сокращением ставится неразрывный пробел: `1000 руб.` -> `1 000 руб.`, `1.5 м` -> `1,5 м`, `220 В` -> `220 В`, `100 Вт` -> `100 Вт`, `2 кВт` -> `2 кВт`, `300 dpi` -> `300 dpi`, `150 lpi` -> `150 lpi`, `30 сентября` -> `30 сентября`.
- Версии и IP-адреса не считаются десятичными дробями и не меняются: `v2.0.1`, `192.168.0.1`.
- Числа внутри кодов и слов с дефисом не разбиваются на разряды: `SALE-2026`.

Полная действующая спецификация доказательств, защит, каталогов и межслойных границ находится в `docs/number-grouping-policy.md`.
- Даты в формате `10.04` и `10.04.2025` не считаются десятичными дробями и не разбиваются на разряды. Если год в дате уже разбит, он собирается обратно: `10.04.2 025` -> `10.04.2025`.
- Исключение для коротких дат: если после `10.04` стоит единица измерения, денежное сокращение или знак валюты, это считается десятичным числом: `10.04 кг` -> `10,04 кг`, `10.04 ₽` -> `10,04 ₽`.
- Точный список обозначений, которые после короткой даты превращают ее в десятичное число: `₽`, `$`, `€`, `%`, `руб.`, `коп.`, `тыс.`, `млн`, `млрд`, `трлн`, `м`, `км`, `кг`, `г`, `мм`, `см`, `л`, `мл`, `шт.`, `с`, `сек.`, `мин.`, `мес.`, `кв.`, `куб.`, `Вт`, `кВт`, `dpi`, `lpi`. Обозначение `В` не входит в это исключение, чтобы дата во фразе `10.04 В Москве` не превращалась в десятичное число.
- Без количественного признака маски, номера карт, счета и другие неизвестные последовательности остаются как введены: `••4444`, `8841475834769921`, `40914810810010073985`.
- Точная защитная подпись или видимая карточная разбивка по четыре символа сохраняет идентификатор и рядом с сильным обозначением: `ID 12345 ₽`, `номер карты 12345 ₽`, `8841 4758 3476 9921 ₽` не получают разрядов.
- Компактная последовательность без защитной подписи рядом с валютой считается суммой; длина сама по себе не используется для угадывания карты или счёта.
- Числа после `№` и `§` не разбиваются на разряды: `№ 12345`.
- Годы от `1000` до `2099` не разбиваются рядом с `г.`, `год`, `году`, `в`, `с`, `по`, `©` и `(c)`: `2024 г.`, `© 2024`.
- Между `©` и годом ставится неразрывный пробел: `©2025` -> `© 2025`.
- Уже испорченный год рядом с копирайтом или `г.` собирается обратно: `© 2 024` -> `© 2024`.
- После числа в `руб.` и `коп.` сохраняется или добавляется точка: `1000 руб 20 коп` -> `1 000 руб. 20 коп.`
- Спецслучай аренды или подписки сохраняется без пробела и точки после `мес`: `5000 ₽/мес` -> `5 000 ₽/мес`.

С точкой нормализуются:

- `тыс.`

- `кв.`

- `гл.`

- `ст.`
- `п.`
- `см.`
- `рис.`
- `стр.`
- `им.`
- `обл.`
- `кр.`
- `пос.`
- `пер.`
- `пр.`
- `просп.`
- `пл.`
- `бул.`
- `наб.`
- `ш.`
- `туп.`
- `оф.`
- `комн.`
- `под.`
- `мкр.`
- `уч.`
- `вл.`
- `влад.`
- `корп.`
- `эт.`
- `пгт.`
- `руб.`

- `т. д.`
- `т. е.`
- `т. к.`
- `т. п.`
- `и т. д.`
- `и др.`
- `и т. п.`
- `в т. ч.`
- `н. в.`
- `P. S.`
- `P. P. S.`
- `мес.`, кроме случая `₽/мес`

Для сокращения `под.` точка добавляется только если сокращение уже написано с точкой или стоит перед номером: `под 2` -> `под. 2`. Обычный предлог не меняется: `под столом`.

Составные сокращения площади и объема:

- `кв. м` -> `кв. м`
- `куб. м` -> `куб. м`

У `м` в этих сочетаниях точка не ставится.

Между сокращениями `д.`, `стр.`, `кв.` и следующим числом ставится неразрывный пробел: `д. 5` -> `д. 5`, `стр. 10` -> `стр. 10`, `кв. 7` -> `кв. 7`.

Без точки нормализуются:

- `млн`
- `млрд`
- `трлн`
- `б-р`
- `пр-т`
- единицы после числа: `с`, `м`, `км`, `кг`, `мм`, `см`, `л`, `мл`, `В`, `Вт`, `кВт`, `dpi`, `lpi`

Если точка после сокращения без точки, единицы измерения или выражения вроде `₽/мес` является концом предложения, она сохраняется. Новым предложением считается ситуация, когда после точки идет пробел и слово с большой буквы в той же строке. Перенос строки и конец текста сами по себе новым предложением не считаются.

Для сокращений без точки точка в конце строки или текста считается лишней точкой сокращения и удаляется: `5 млрд.` -> `5 млрд`, `5 кг.` -> `5 кг`, `5000 ₽/мес.` -> `5 000 ₽/мес`.

Примеры с точкой конца предложения:

- `100 млн. Компания растёт.` -> `100 млн. Компания растёт.`
- `5 кг. Доставим завтра.` -> `5 кг. Доставим завтра.`
- `5000 ₽/мес. Следующий платёж завтра.` -> `5 000 ₽/мес. Следующий платёж завтра.`

Примеры с лишней точкой сокращения:

- `100 млн. рублей.` -> `100 млн рублей.`
- `5 кг. товара.` -> `5 кг товара.`
- `5000 ₽/мес доступна всем.` -> `5 000 ₽/мес доступна всем.`
- `5 кг.` -> `5 кг`
- `5000 ₽/мес.` -> `5 000 ₽/мес`

Примеры:

- `100 млн.` -> `100 млн`
- `5 млрд.` -> `5 млрд`
- `100 тыс` -> `100 тыс.`
- `20 кв м` -> `20 кв. м`
- `6 мес` -> `6 мес.`

### 7. Неразрывные пробелы

Неразрывный пробел `U+00A0` ставится:

- перед длинным тире: `Москва — столица`;
- после отдельных кириллических слов из 1–2 букв, но не после части слова через дефис: `что‑то на Авито`;
- в инициалах: `И.И. Иванов` -> `И. И. Иванов`, `И.Иванов` -> `И. Иванов`;
- после `№` и `§` перед числом;
- между числом и месяцем, единицей измерения или денежно-числовым сокращением: `30 сентября`, `5 кг`, `220 В`, `100 Вт`, `2 кВт`, `300 dpi`, `150 lpi`, `100 млн`, `20 °C`;
- между словами из whitelist и следующим числом или компактным диапазоном с процентом: `скидка 5%` -> `скидка 5%`, `скидка 5-10%` -> `скидка 5—10%`, `кэшбэк 10%` -> `кэшбэк 10%`, `НДС 20%` -> `НДС 20%`. Правило не применяется ко всем словам подряд: `оборот 7%` остается с обычным пробелом;
- между обычным числом и следующим словом, если число не является телефоном, номером после `№`, параграфом после `§`, годом или частью кода: `15 завтра` -> `15 завтра`, `10000 клиентов` -> `10000 клиентов`. Это правило связывает число со словом, но не доказывает разрядную группировку;
- неразрывный пробел слева от короткого слова не мешает этому правилу: `По 2000 человек` -> `По 2 000 человек`;
- если число уже связано слева числовым правилом, дополнительная связка со следующим словом не добавляется: `д. 5 живёт` -> `д. 5 живёт`, `г. 10000 жителей` -> `г. 10 000 жителей`;
- перед частицами `ли`, `же`, `бы`, `ль`, `ж`, `б`: `далеко ли` -> `далеко ли`, `он же` -> `он же`, `сказал бы` -> `сказал бы`, `можно ль` -> `можно ль`;
- после частиц `ли`, `же`, `бы`, `ль`, `ж`, `б` правило коротких слов не ставит неразрывный пробел: `далеко ли холодно` -> `далеко ли холодно`;
- после дат в формате `9.05`, `09.05`, `9.05.2026` и `09.05.2026` неразрывный пробел не ставится;

### 8. Математика и символы

- Математические примеры с минимум двумя числами и оператором `+`, `*`, `×`, `x`, `х`, `/` или `=` оформляются с неразрывными пробелами вокруг знаков: `10 x 20 = 200` -> `10 × 20 = 200`.
- `x`, `х` или `*` между числами заменяются знаком умножения: `2*2` -> `2 × 2`, `2 * 2` -> `2 × 2`.
- В примерах сложения, умножения, деления и равенства вокруг знаков ставятся неразрывные пробелы: `5 + 5` -> `5 + 5`, `6 / 2 = 3` -> `6 / 2 = 3`.
- Дефис или тире между числами считается вычитанием только в математическом контексте: если в выражении есть `=`, другой математический оператор, больше одного оператора или унарный минус перед первым числом.
- Для вычитания и отрицательных чисел используется знак минус `−`, а не дефис или среднее тире: `10 - 5 = 5` -> `10 − 5 = 5`, `−10 + 5 = −5` -> `−10 + 5 = −5`.
- Отрицательное число пишется слитно со знаком минуса: `-10` -> `−10`.
- Два компактных числа через дефис или тире без математического контекста остаются диапазоном с длинным тире: `5 - 5` -> `5—5`, `10-20` -> `10—20`.
- Телефоны, даты, версии, IP, URL, email, переменные и промокоды не считаются математическими примерами.
- Отдельные дроби заменяются символами: `1/2` -> `½`, `1/4` -> `¼`, `3/4` -> `¾`.
- Дроби внутри слов и версий не трогаются: `v1/2`.
- Одиночный знак градуса пишется слитно с числом: `20 °` -> `20°`. Температура по Цельсию и Фаренгейту нормализуется с неразрывным пробелом и знаком градуса: `20C`, `20 C`, `20 °C` -> `20 °C`; `100F` -> `100 °F`.
- `(c)` заменяется на `©`.
- `(tm)` заменяется на `™`.
- `(r)` заменяется на `®`.
- `->` и `=>` заменяются на `→`.
- Диапазоны температур со знаками `+` или `−` разделяются многоточием: `+5-+10 C`, `+5...+10 °C` -> `+5…+10 °C`.

## Как запустить локально

1. Установить зависимости:

```bash
npm install
```

2. Запустить сборку в watch-режиме:

```bash
npm run dev
```

3. В Figma Desktop открыть:

`Plugins` -> `Development` -> `Import plugin from manifest...`

4. Выбрать файл `manifest.json` из корня проекта.

После этого Figma будет запускать собранный файл `dist/code.js`. Если `npm run dev` продолжает работать, изменения из `src/code.ts` будут пересобираться автоматически.

## Структура проекта

- `src/code.ts` — исходный TypeScript-код плагина.
- `src/ui.html` — интерфейс настроек, окон ошибок и сообщения о выпуске, который Figma получает как готовый HTML.
- `src/ui-content.js` — весь текстовый контент вкладок `Типограф`, `Правила` и `О плагине`.
- `src/release-announcements.js` — активное сообщение выпуска и архив его экранов: строка меню, текст, иллюстрация и кнопки.
- `scripts/sync-ui-content.js` — синхронизирует тексты вкладок и сообщение с `src/ui.html`, вкладывает локальные файлы внутрь интерфейса и обновляет временный пункт в `manifest.json`.
- `dist/code.js` — собранный JavaScript, который запускает Figma.
- `manifest.json` — манифест Figma-плагина, указывает на `dist/code.js`.
- `package.json` — npm-скрипты и зависимости.
- `tsconfig.json` — настройки TypeScript. Используется `target: ES2017`, `module: none` и `outFile: dist/code.js`, чтобы собранный файл был совместим с рантаймом Figma Plugin API.
- `assets/plugin-icon.svg` — иконка плагина для публикации и локального предпросмотра. В `manifest.json` она не подключается: Figma задает иконку плагина через окно публикации или обновления ресурса.
- `assets/announcements` — сохранённые иллюстрации сообщений о выпусках. Старые варианты не удаляются, чтобы их можно было вернуть.
- `docs/plugin-analytics.md` — единое подробное описание аналитики плагина: путь данных из Figma в PostHog и Telegram, события, дашборды, отчёты, команды, приватность и проверка системы.

## Текущее состояние и планы

Текущее состояние проекта — рабочий быстрый запуск, интерфейс настроек, окно проблемных слоёв и опциональный экран сообщения о выпуске. Быстрый запуск не открывает UI во время успешной обработки, но открывает окно, если нужно показать конкретные пропущенные или потенциально повреждённые слои. Сообщение о выпуске открывается только вручную из отдельной строки меню.

Подробная последовательность следующих технических этапов хранится в `docs/development-roadmap.md`.

Команда `⭐ Продвинутые фичи` открывает UI. Вкладка `Типограф` запускает режим `Для красоты` или режим `Для разработки` и передает в ядро настройки `Обработать даже слои с замочком`, `Обработать даже скрытые слои` и `Считать все одиночные * пробелами`. Во время обработки кнопка показывает индикатор и не допускает повторного запуска. После обработки из окна настроек UI остается открытым, чтобы пользователь мог запускать следующую обработку без повторного открытия плагина. Дальше интерфейс нужно развивать поэтапно, не ломая быстрый запуск.

### Вкладки UI

В интерфейсе есть три вкладки:

- `Типограф` — рабочая вкладка для запуска обработки. Умеет запускать режимы `Для красоты` и `Для разработки`, а также управлять обработкой заблокированных, скрытых слоев и разбором существующих звездочек в режиме разработки.
- `Правила` — короткое описание правил типографики, оформленное аккордеонами. Аккордеон `Обычные пробелы` стоит после `Неразрывные пробелы`, чтобы было ясно, почему в правилах есть несколько тем про пробелы.
- `О плагине` — текстовый блок о плагине, авторе и ссылка на канал.

Контент вкладок отделен от рабочей логики плагина, чтобы можно было спокойно править тексты и экспериментировать с подачей без риска сломать типографику.

Текущая структура контента:

- `src/ui-content.js` — единый источник текстов вкладок, пунктов правил, подписей режимов и кнопок.
- `src/ui.html` — готовый HTML для Figma. В нем есть размеченные блоки `chistovik-content:*`, которые обновляет скрипт синхронизации.
- `scripts/sync-ui-content.js` — генератор, который переносит данные из `src/ui-content.js` в `src/ui.html`.
- `scripts/send-daily-analytics.js` — скрипт ежедневного Telegram-отчета по PostHog-аналитике.
- `scripts/lib/daily-report-delivery.js` — общая отправка ежедневного отчёта с защитой от пропусков и повторов.
- `scripts/lib/daily-report-delivery-store.js` — служебная отметка о состоянии доставки отчёта за конкретную дату.
- `scripts/configure-telegram-menu.js` — скрипт обновления команд и подписей в меню Telegram.
- `scripts/lib/analytics-report.js` — общая логика PostHog-запросов, форматирования Telegram-сообщений и отправки сообщений.
- `api/telegram.js` — Vercel endpoint для Telegram webhook и команд `/today`, `/speed` и `/errors`.
- `api/daily-analytics.js` — Vercel endpoint для ежедневного Telegram-отчета за вчера.
- `api/capture.js` — Vercel endpoint, который принимает события от Figma и надёжно сохраняет их во временную очередь.
- `api/queues/posthog.js` — закрытый обработчик временной очереди с повторной доставкой в PostHog.
- `scripts/lib/analytics-capture.js` — проверка входящих событий, сохранение в очередь и логика пересылки в PostHog.

Важный технический нюанс: Figma-плагин не читает отдельные локальные файлы контента во время работы. Поэтому контент хранится отдельно для удобного редактирования, но встраивается в `src/ui.html` перед сборкой. Команды `npm run build` и `npm run dev` сначала запускают `npm run sync-ui`.

### Производительность

В `manifest.json` включено поле:

```json
"documentAccess": "dynamic-page"
```

Это значит, что Figma не должна заранее загружать все страницы файла перед запуском плагина. Команда `⭐ Продвинутые фичи` открывает UI без обхода документа. Если пользователь выбрал текстовый слой, фрейм, группу, компонент или другой контейнер, плагин обходит только выделение и не вызывает `figma.currentPage.loadAsync()` заранее. Если ничего не выбрано, плагин явно загружает текущую страницу через `figma.currentPage.loadAsync()` и ищет все текстовые слои через `findAllWithCriteria({ types: ["TEXT"] })`. Успешно загруженные одинаковые шрифты переиспользуются для остальных текстовых слоёв. Неудачная попытка запоминается только до конца текущего запуска: другие слои с тем же шрифтом получают ошибку сразу, а новый запуск снова пробует загрузить шрифт.

Для ускорения обхода включается `figma.skipInvisibleInstanceChildren = true`, если пользователь не просит обрабатывать скрытые слои. Это позволяет не заходить в скрытые слои внутри инстансов.

Состояние общих скрытых и заблокированных родителей, уже загруженные шрифты и неизменившиеся служебные данные переиспользуются в пределах запуска. В старом режиме полной записи также переиспользуются уже проверенные стили и переменные Figma.

В опубликованной сборке от 6 августа 2026 года уже используется точечная запись текста. Плагин сначала получает прежний итоговый текст, затем рассчитывает вставки, удаления и замены и применяет их с конца строки. Весь текстовый слой больше не перезаписывается через `textNode.characters`. Расчёт работает с целыми видимыми символами и не разрезает эмодзи и сложные составные знаки. Для длинных текстов используется ограниченный поиск ближайшего устойчивого совпадения вместо тяжёлого сравнения всей строки. Тысячи близких исправлений внутри одного участка с одинаковым оформлением могут объединяться в одну операцию только тогда, когда между соседними исправлениями нет большого неизменяемого фрагмента. Все действующие примеры типографики дополнительно проходят через настоящую точечную запись в автоматических тестах.

После точечной записи плагин сверяет итоговый текст и фактическое оформление каждого символа с исходным планом — в том числе у слоя со смешанными стилями, подчёркиваниями и несколькими библиотечными связями. Если проверка не пройдена, плагин возвращает исходное состояние только проблемного слоя и проверяет его повторно. Возврат выполняется обратными точечными операциями и никогда не присваивает слою всю исходную строку. Если первая операция упала до фактического изменения, плагин сначала подтверждает, что слой и так остался исходным, и ничего в него не записывает. Подтверждённый возврат считается обычной ошибкой слоя: плагин продолжает обрабатывать остальные. Критическое уведомление и остановка нужны только тогда, когда исходный текст, внешний вид или компонентные связи проблемного слоя подтвердить не удалось. Старая полная запись пока сохранена только как внутренний переключатель сборки и не запускается автоматически после ошибки.

Перед точечной записью плагин защищается от изменений во время ожидания Figma. Если поменялся текст, запись не начинается и показывается отдельное согласованное уведомление. Если поменялось оформление, плагин принимает новое состояние, повторно загружает нужные шрифты и продолжает только после стабилизации. Точечная запись не открывает библиотечные стили, переменные и главные компоненты через Figma API, потому что не переподключает их; после записи она сравнивает сохранённые на самом слое идентификаторы, свойства оформления, цепочку родителей и привязку текста к свойству компонента. На подготовку даётся не больше трёх попыток; если оформление продолжает меняться, слой остаётся нетронутым. Удалённый слой исключается из обработки и не мешает остальным слоям, а отсутствие нужного ресурса не считается удалением слоя и остаётся обычной ошибкой.

### Режимы типографа

Поддерживаются два режима:

- `Для красоты` — основной режим, текущая логика. В тексте используются настоящие неразрывные пробелы `U+00A0`.
- `Для разработки` — типографика применяется так же, но вместо неразрывных пробелов в текст вставляется символ `*`.

Режимы должны отличаться только способом отображения неразрывного пробела. Все остальные правила типографики остаются одинаковыми.

В режиме `Для разработки`:

- все позиции, где в основном режиме должен быть `U+00A0`, отображаются символом `*`;
- типографские `*` окрашиваются в `#FF4053`;
- пользовательские `*`, не связанные с типографикой, не перекрашиваются и не считаются маркерами неразрывного пробела;
- окрашивание сохраняет остальные стили текста настолько аккуратно, насколько позволяет Figma Plugin API.

Если в режиме `Для разработки` включена галочка `Считать все одиночные * пробелами`, плагин проверяет уже существующие пользовательские `*` как возможные места пробелов. Безопасные одиночные `*` превращаются в обычный пробел перед применением правил, а затем типограф сам решает, останется это обычным пробелом или станет красным служебным маркером неразрывного пробела: `Что*нужно` -> `Что нужно`, `их*комбинации` -> `их*комбинации` с красной служебной звездочкой. Небезопасные `*` в масках, сериях, математике, markdown, латинице, кодах и сносках остаются пользовательскими.

При переключении из режима `Для разработки` в режим `Для красоты` плагин не заменяет все `*` на неразрывные пробелы. Он:

1. Берет текущий текст.
2. Получает список уже существующих development-маркеров по сохраненным plugin data и по стилю/цвету `#FF4053`.
3. Восстанавливает в пробел только те `*`, чьи индексы пришли в `existingDevelopmentMarkerIndexes`.
4. Повторно прогоняет правила типографики.
5. Остальные `*` оставляет пользовательскими символами без угадывания по контексту.

Это нужно, чтобы не ломать маскированные данные, математические выражения, сноски и любые пользовательские звёздочки.

Важно: служебными считаются только те `*`, которые уже были созданы плагином как development-маркеры и найдены по сохраненным индексам или по стилю/цвету. Plugin data используется только если сохраненный текст полностью совпадает с текущим текстом ноды; если текст вручную изменили, старые индексы игнорируются. Если индекс маркера не передан, `*` остается пользовательским символом и может участвовать в других правилах, например `2 * 2 = 4` должно стать `2 × 2 = 4`.

Повторный запуск режима `Для разработки` дополнительно защищает устойчивые уже-типографированные паттерны: телефоны, суммы, годы рядом с `©` и разрядные числа со `*` не должны попадать в математическое правило и превращаться в умножение. Это ограниченная защита форматов вроде `+7*900*123‑45‑67`, `1*000*₽`, `©*2025`, `812*345*678*901*234`; произвольные пользовательские `*` не удаляются и не превращаются в пробел.

Телефоноподобные последовательности после `№` считаются номером заказа, а не телефоном: `№ +7 900 123-45-67` не приводится к телефонному формату и при повторном запуске `Для разработки` не превращается в математическое выражение.

### Настройки запуска

В коде есть единый объект настроек `PluginRunOptions`:

```ts
{
  mode: "beauty" | "development",
  processHiddenNodes: boolean,
  processLockedNodes: boolean,
  recolorExistingAsterisks: boolean
}
```

Текущие значения по умолчанию:

- `mode: "beauty"`;
- `processHiddenNodes: false`;
- `processLockedNodes: false`.
- `recolorExistingAsterisks: false`.

Чекбокс `Обработать даже слои с замочком` выключен по умолчанию. Замок в макете считается намерением дизайнера не менять слой. Если чекбокс включен, обработка затрагивает заблокированные тексты и тексты внутри заблокированных родителей.

Чекбокс `Обработать даже скрытые слои` выключен по умолчанию. Если чекбокс включен, обработка затрагивает скрытые тексты и тексты внутри скрытых родителей, а также отключает пропуск скрытых слоев внутри инстансов.

Чекбокс `Считать все одиночные * пробелами` доступен только в режиме `Для разработки` и выключен по умолчанию. Если он включен, безопасные одиночные `*` разбираются как пробельные кандидаты: часть становится обычными пробелами, а часть — служебными development-маркерами, если на этом месте по правилам нужен неразрывный пробел. После такого запуска режим `Для красоты` воспринимает только красные служебные `*` как неразрывные пробелы.

### Окно проблемных слоёв

Дизайн пользовательского окна полностью согласован в `preview/error-report-preview.html` и перенесён в рабочий плагин. Полностью успешные запуски продолжают показывать небольшое финальное уведомление Figma, а неполная обработка и ошибки показываются в отдельном окне.

Окно имеет тот же размер, что настройки, и заменяет красное уведомление во всех режимах запуска. В нём предусмотрены три состояния:

- `Не всё удалось обработать` — отдельный слой не изменён, но исходное состояние безопасно восстановлено; плагин продолжает обрабатывать следующие слои;
- `Типограф остановил работу` — плагин не смог подтвердить восстановление текста, стилей или связи с компонентом и остановился, чтобы не увеличивать риск;
- `Не удалось запустить типограф` — ошибка произошла до начала обработки, поэтому в макетах ничего не изменилось и списка слоёв нет.

В списке показываются фрагмент текста, путь слоя и счётчики. Первый слой выбирается автоматически; клик и стрелки выделяют слой в Figma и прокручивают к нему макет. После запуска из настроек есть кнопка `Вернуться к типографу`, после быстрого запуска кнопки нет. Подробные технические причины пользователю не показываются.

Фрагменты из окна ошибок, названия и пути проблемных слоёв остаются только внутри Figma и не отправляются в PostHog или Telegram. В постоянную аналитику ошибок разрешены только безопасные категории и агрегированные счётчики. Временная диагностика чисел описана отдельно выше и в `docs/number-diagnostics.md`.

Окно не меняет правила типографики, порядок правил, поведение режимов, стратегию development-маркеров и сохранение оформления. Полная логика, точные тексты и проверки находятся в `docs/error-ui-plan.md`, визуальная система — в `docs/ui-design-system.md`.

### Правила развития проекта

- Рабочая типографика должна оставаться отделенной от UI.
- Правила типографики считаются критической зоной: нельзя менять `cleanTypography`, порядок правил, регулярные выражения, исключения и тестовые ожидания ради UI-отчета, аналитики или Telegram-логов.
- Аналитика должна оставаться отделенной от правил типографики и не должна менять поведение `cleanTypography`.
- Ежедневный Telegram-отчет должен жить отдельно от Figma-плагина: основной запуск через GitHub Actions в 09:17 по Москве, запасной через Vercel Cron в следующем часовом окне и общая защита от повторной отправки, без влияния на запуск плагина в Figma.
- Telegram-команды должны жить отдельно от Figma-плагина: через Vercel endpoint `api/telegram.js`, без изменений `src/code.ts`, `dist/code.js`, `src/ui.html`, `src/ui-content.js` и `manifest.json`.
- Быстрый запуск не должен зависеть от состояния открытого интерфейса.
- UI должен передавать настройки в основную логику сообщением, а не дублировать правила обработки.
- Тексты вкладок должны храниться в `src/ui-content.js`, отдельно от ядра типографики.
- Перед изменением текстов вкладки `Правила` нужно сначала прислать пользователю новые формулировки и вносить их только после явного согласования.
- Нельзя добавлять или менять никакие видимые пользователю тексты без прямого предварительного согласования с пользователем. Это относится ко всем уведомлениям Figma, сообщениям об успехе и ошибках, состояниям загрузки, подписям кнопок и настроек, вкладкам, подсказкам, пустым состояниям и диагностическим отчетам. Даже технически необходимый новый текст сначала нужно показать пользователю дословно и получить явное согласие.
- Не загружать все страницы файла без необходимости. Плагин должен оставаться совместимым с `documentAccess: "dynamic-page"` и работать только с текущей страницей.
- Не использовать `typograf`, если его правила могут конфликтовать с кастомной логикой.
- Не пересоздавать текстовые слои и не заменять их новыми нодами.
- Продолжать менять текст точечно через `deleteCharacters` и `insertCharacters`. Полная запись строки может оставаться только внутренним переключателем для отката сборки и не должна автоматически запускаться после ошибки.
- Не отправлять в аналитику текст макета, названия файлов, страниц, слоев, email, имя пользователя или Figma user id.
- Ошибки аналитики не должны блокировать работу плагина и не должны показываться пользователю.
- После любых замен длины текста проверять mixed styles и цветовые диапазоны.
- Перед коммитом нужно написать пользователю полный список изменений, которые попадут в коммит: не только запрошенное изменение, но и все сопутствующие изменения поведения, текстов, уведомлений, настроек, README, сборки и manifest. Если меняются уведомления, нужно явно показать новые тексты уведомлений до коммита.
- Каждую версию сохранять отдельным локальным git-коммитом на русском языке с понятным описанием изменений.
- Если пользователь просит сделать коммит, после успешных проверок нужно создать коммит и самостоятельно выполнить `git push` текущей ветки в `origin`. Оставлять коммит только локально нужно лишь по явной просьбе пользователя.
- После каждого коммита дополнять `docs/commit-log.md`: указывать код коммита, что изменилось, зачем это было сделано, какие проверки прошли и что важно не потерять в следующем чате.
- После каждого этапа давать инструкцию, как проверить в Figma, что ничего не сломалось.

## Журнал коммитов

Полный журнал коммитов вынесен в `docs/commit-log.md`, чтобы README не разрастался. После каждого нового локального коммита нужно добавлять запись на русском языке именно туда: с кодом коммита, смыслом изменений, затронутыми файлами, проверками и важными договоренностями для следующего чата.

## Технические ориентиры

- Главная функция обработки текста: `cleanTypography`.
- Основной запуск проходит через объект настроек `PluginRunOptions`: режим `beauty` или `development`, флаг `processLockedNodes`, флаг `processHiddenNodes` и флаг `recolorExistingAsterisks`.
- Порядок правил важен и зафиксирован внутри `cleanTypography`.
- Правило `Сочетание !?: !? → ?!` применяется только к отдельной паре `!?`. Более длинные смешанные сочетания вопросительных и восклицательных знаков не сокращаются до `?!`.
- При возврате из режима `Для разработки` в `Для красоты` нельзя угадывать служебные `*` по общим типографским правилам: источником истины для обычных маркеров являются `existingDevelopmentMarkerIndexes`, собранные по plugin data и по стилю/цвету. Сохраненные plugin data можно использовать только при полном совпадении сохраненного текста с текущим текстом ноды. Отдельно разрешена только ограниченная защита уже-типографированных телефонов, сумм и разрядных чисел, чтобы повторный запуск development не превращал их в математику.
- Не менять стратегию на пересоздание текстовых слоев: это сломает стили и связи в макете.
- Не обрабатывать заблокированные слои по умолчанию: это считается намерением дизайнера не менять слой. В UI уже есть чекбокс `Обработать даже слои с замочком`, который передает в ядро `processLockedNodes`.
- Не обрабатывать скрытые слои по умолчанию. В UI уже есть чекбокс `Обработать даже скрытые слои`, который передает в ядро `processHiddenNodes`.
- Если добавляются новые правила, нужно проверять повторный запуск плагина: результат должен быть идемпотентным.
- Для правил с заменой длины текста нужно следить за сохранением mixed styles. Сейчас точечные операции заранее получают источник оформления, а после записи результат сверяется с картой ожидаемого оформления каждого символа.
- Коммиты нужно писать на русском языке. Сообщение коммита должно объяснять суть версии так, чтобы через время было понятно, какие изменения вошли и к какой версии можно откатиться.
- После запроса на коммит самостоятельно выполнять push текущей ветки в `origin`, если пользователь явно не попросил оставить коммит локальным.
- После правок кода запускать:

```bash
npm run build
```

### Автоматические проверки

Главная команда полной проверки:

```bash
npm test
```

Она сначала собирает плагин, затем проверяет правила типографики, повторный запуск на уже обработанном тексте, сохранение оформления, работу с библиотечными текстовыми стилями, переменными, списками, ссылками и вложенными компонентами, обработку нескольких начертаний внутри одного слоя, защиту телефонов и банковских номеров, точечную запись длинных и плотно изменяемых текстов, возврат исходного состояния при ошибке, момент создания контрольной точки Figma, ограничение времени ожидания, а также расчёты аналитики и Telegram-отчётов. Отдельный большой набор сравнивает новые ускоренные расчёты с прежними проверенными вариантами на случайных и повторяющихся текстах, чтобы оптимизация не меняла результат.

Workflow `.github/workflows/tests.yml` запускает ту же команду в GitHub после каждого push, для pull request и вручную. Поэтому перед публикацией действует двойная проверка: сначала `npm test` локально, затем результат `Автоматические тесты / Сборка и тесты` в GitHub Actions.

Автоматические тесты работают на модели Figma API и не могут полностью воспроизвести серверную библиотеку компонентов. Связь реального инстанса с библиотекой после обновления плагина дополнительно проверяется вручную по `docs/figma-regression-checklist.md`.
