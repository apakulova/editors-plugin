# Сообщения о выпуске в меню плагина

Этот механизм нужен для временных сообщений о важных изменениях. Сообщение появляется отдельной строкой в меню Figma после разделителя и открывает экран внутри обычного окна Чистовика.

Одновременно может быть активно только одно сообщение. Оно не открывается автоматически: пользователь видит его только после нажатия на строку в меню или в недавних действиях Figma. Чистовик не хранит отметку о просмотре или закрытии сообщения и не отправляет отдельную аналитику об открытии экрана или нажатиях на его кнопки.

## Ограничения меню Figma

Строка сообщения находится в системном меню Figma, поэтому плагин не управляет её оформлением.

- Шрифт, цвет и начертание изменить нельзя.
- Перенос на вторую строку включить нельзя.
- Figma сама задаёт ширину и может завершить длинную строку многоточием.
- Перед сообщением можно поставить системный разделитель, но нельзя добавить собственную подложку или декоративный блок.

Поэтому название нужно проверять в настоящем меню Figma и делать достаточно коротким. Утверждённая строка текущего выпуска: `⚠️ Не все числа делятся на разряды →`.

## Как включить или убрать сообщение

Источник всех сообщений — `src/release-announcements.js`.

- `activeId` содержит код сообщения, которое должно быть показано в текущем выпуске.
- `activeId: null` убирает строку и разделитель из меню при следующей сборке, но не удаляет текст и иллюстрации из истории.
- После любого изменения нужно выполнить `npm run build`: сборка обновит `manifest.json`, вставит экран в `src/ui.html` и положит иллюстрацию внутрь плагина.

Figma может некоторое время хранить старую команду в недавних действиях. Если пользователь нажмёт её после выключения сообщения, Чистовик откроет обычную вкладку `Типограф`: пустого окна и устаревшего сообщения не будет.

Figma не позволяет менять меню уже опубликованной версии на расстоянии. Чтобы добавить или убрать строку, нужно собрать и опубликовать новую версию плагина.

### Добавить новое сообщение

1. Создать в `items` новую запись с уникальным кодом. Удобный формат кода: короткая тема и дата выпуска, например `feature-name-2026-09`.
2. Не перезаписывать прежнюю запись: старые тексты должны оставаться в `items`, чтобы сообщение можно было вернуть без восстановления по истории Git.
3. Сохранить новую иллюстрацию в `assets/announcements` под новым понятным именем. Старые иллюстрации не удалять и не заменять файлом с тем же именем.
4. Заполнить строку меню, заголовок, абзацы и кнопки. Все видимые тексты сначала согласовать дословно.
5. Указать код новой записи в `activeId`.
6. Добавить в конец этого документа новый раздел `Архив` с утверждённым текстом, кнопками и всеми сохранёнными вариантами иллюстрации.
7. Обновить раздел `Команды` и описание структуры в README, если название активной строки или состав файлов изменились.
8. Вручную обновить `preview/announcement-preview.html`: этот макет не создаётся автоматически и может разойтись с настоящим экраном плагина.
9. Выполнить `npm test`, затем пройти раздел `Сообщение о выпуске` из `docs/figma-regression-checklist.md` в настоящей Figma.
10. Опубликовать новую версию плагина. Без публикации меню пользователей не изменится.

### Выключить сообщение

1. Установить `activeId: null`.
2. Не удалять запись из `items`, её иллюстрации и архивное описание ниже.
3. Обновить раздел `Команды` в README: отметить, что в текущем выпуске активного сообщения нет.
4. Выполнить `npm test` и опубликовать новую версию.

При сборке строка сообщения и стоящий перед ней разделитель исчезнут из `manifest.json`. Если Figma сохранила старую команду в недавних действиях, нажатие откроет обычную вкладку `Типограф`.

### Вернуть старое сообщение

1. Найти нужный код в `items` и сверить текст и иллюстрацию с архивом в этом документе.
2. Указать этот код в `activeId`.
3. Убедиться, что файл иллюстрации всё ещё лежит в `assets/announcements`.
4. Обновить раздел `Команды` в README в соответствии с возвращённой строкой меню.
5. Выполнить `npm test`, проверить экран в Figma и опубликовать новую версию.

Если нужно вернуть только старую картинку в новое сообщение, создать для нового сообщения отдельную запись и сослаться в ней на сохранённый файл. Старую архивную запись менять не нужно.

## Состав сообщения

Для каждого сообщения хранятся:

- текст строки в меню;
- иллюстрация;
- заголовок;
- один или несколько абзацев;
- одна или две кнопки.

Готовая форма записи:

```js
"<уникальный-код>": {
  menuName: "<короткая строка меню>",
  imageAsset: "announcements/<имя-файла>.png",
  titleHtml: "<заголовок>",
  paragraphsHtml: [
    "<первый абзац>",
    "<второй абзац>",
  ],
  actions: [
    {
      action: "back-to-typograph",
      appearance: "primary",
      labelHtml: "<текст кнопки>",
    },
  ],
},
```

Заголовок, абзацы и подписи кнопок хранятся как готовая разметка для экрана. Для типографики используются:

- `&nbsp;` — неразрывный пробел;
- `<strong>...</strong>` — жирный фрагмент;
- `<br>` — перенос внутри одного абзаца.

Произвольные теги и стили добавлять нельзя: экран должен оставаться в общей дизайн-системе. Перед сборкой нужно отдельно проверить висячие предлоги, выделение жирным и то, что стрелка между примерами не стала жирной.

Иллюстрация должна быть PNG с настоящим прозрачным фоном. Сборка превращает её во внутренние данные страницы, поэтому экран работает без загрузки картинки из интернета.

Кнопка возврата к типографу обязательна. Если кнопок две, одна должна быть основной зелёной, другая — вторичной салатовой с границей. Одна кнопка может быть основной или вторичной — в зависимости от смысла сообщения.

Порядок записей в `actions` определяет порядок кнопок на экране сверху вниз.

Доступные действия кнопок:

- `back-to-typograph` — открыть вкладку `Типограф`;
- `show-rules` — открыть вкладку `Правила`.

Новых действий без отдельной разработки нет. Сборка проверяет структуру сообщения и остановится с понятной ошибкой, если не хватает кнопки, иллюстрации или другого обязательного поля.

## Источники правды

- Активность сообщения, тексты, иллюстрация и кнопки: `src/release-announcements.js`.
- Фактический пункт меню после сборки: `manifest.json`.
- Разметка и поведение настоящего экрана: `src/ui.html`.
- Визуальные размеры и стили: `docs/ui-design-system.md`.
- Ручные проверки в Figma: `docs/figma-regression-checklist.md`.
- История утверждённых сообщений и картинок: разделы `Архив` в этом документе.
- Локальный макет: `preview/announcement-preview.html`. Он обновляется вручную и не является источником текста для сборки.

## Архив: `number-grouping-2026-08`

Строка в меню:

> ⚠️ Не все числа делятся на разряды →

Заголовок:

> Чистовик больше не делит все числа по разрядам

Текст:

> Пробел теперь ставится только у чисел рядом с валютой, процентом или единицами измерения. В остальных случаях — решение за редактором.
>
> Здесь поменяется: **10000 ₽** → **10 000 ₽**<br>
> Тут без правок: **Разыграем 20000 пылесосов**

Кнопка: `Вернуться к типографу`, основная зелёная.

Текущая иллюстрация: `assets/announcements/number-grouping-v3.png`.

Сохранённые варианты иллюстрации:

- `assets/announcements/number-grouping.png` — первый вариант;
- `assets/announcements/number-grouping-v2.png` — вариант с маленькой коралловой звёздочкой;
- `assets/announcements/number-grouping-v3.png` — утверждённый вариант с крупной коралловой звёздочкой.

Локальный макет экрана: `preview/announcement-preview.html`.
